# โมเดลวิเคราะห์ผิวรายโซน (Zone classifier)

ขั้นตอนนี้แบ่งใบหน้าเป็น 5 ส่วน ได้แก่ **หน้าผาก, แก้ม 2 ข้าง, จมูก, ใต้ตา, คาง** แล้วให้โมเดลวิเคราะห์ผิวทีละส่วน
ส่วนละ 6 ปัญหา คือ สิว จุดด่างดำ ถุงใต้ตา ความมัน รอยแดง และริ้วรอย (multi-label classification)
เป้าหมายคือวัดผลด้วย **Accuracy / F1** ให้ได้ 80–90%

```
ภาพใบหน้า ─► MediaPipe FaceMesh (468 จุด) ─► 6 polygon ─► ครอปทีละโซน 224×224 ─► CNN + zone embedding ─► 6 ความน่าจะเป็น/โซน
```

| ไฟล์ | หน้าที่ |
|---|---|
| `ai-service/face_zones.py` | แบ่งโซนจาก landmark และครอปภาพ ใช้โค้ดชุดเดียวกันทั้งตอนเทรนและใน API |
| `ai-service/zone_model.py` | โครงสร้างโมเดลและตัวโหลดสำหรับ API |
| `zone_train/build_zone_dataset.py` | แปลง dataset กรอบ YOLO (`dataset_clean_v2`) เป็น dataset รายโซน |
| `zone_train/train_zone_classifier.py` | เทรนโมเดล ปรับ threshold บน valid และวัดผลบน test (Accuracy, Precision, Recall, F1, AUC) |
| `zone_train/review_tool.py` + `.html` | หน้าเว็บในเครื่องสำหรับตรวจ/แก้ label รายโซน (เปิดด้วย `review_labels.bat`) |

- ชุด `img-*` มีแค่ wrinkle

ถ้านับกรณี "ไม่มีกรอบสิว" ในชุดเหล่านี้ว่าเป็น "ไม่มีสิว" เราจะสอนโมเดลผิด และได้ค่าความแม่นยำที่ไม่จริง
สคริปต์จึงตั้งค่าเป็น -1 แล้วไม่นำไปคิดทั้งใน loss และใน metric กรณีที่ได้ -1 มีดังนี้
- คลาสที่แหล่งข้อมูลนั้นไม่เคย label
- กรอบใหญ่ที่แตะโซนเพียงนิดเดียว
- ภาพที่ไม่มี label เลย เพราะตรวจแล้วพบภาพที่เห็นสิว/จุดชัดแต่ไม่มีกรอบ

ภาพซูมใกล้ที่ไม่เห็นทั้งใบหน้ามีประมาณ 1/4 ของ dataset ภาพกลุ่มนี้แบ่งโซนไม่ได้ สคริปต์จึงเก็บไว้เป็นตัวอย่างชนิด `patch`
เพื่อใช้ช่วยสอนลักษณะของสิว/จุดในระยะใกล้ แต่แยกรายงานผลออกจากคะแนนรายโซน

## 3. เทรน + วัดผล (RTX 3070 ประมาณ 20–40 นาที)

```bat
python "%REPO%\zone_train\train_zone_classifier.py" --data zone_dataset --arch efficientnet_b0 --epochs 40 --batch 64 --workers 4
```

ผลลัพธ์จะอยู่ใน `runs_zone\<ชื่อรัน>\`

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `report_test.md` | **ตารางผลบน test set สำหรับใส่ในเล่ม** มี Macro-F1, Accuracy, Precision, Recall, F1, AUC ต่อคลาส และ Accuracy/F1 ต่อโซน |
| `metrics_test.json` | ตัวเลขชุดเดียวกันในรูป JSON |
| `curves.png` | กราฟ loss และ F1 ต่อ epoch |
| `best.pt` | ไฟล์โมเดลที่จะนำไป deploy |

**ควรรายงานตัวเลขไหน:** ใช้ **Macro-F1** เป็นตัวเลขหลัก และรายงานคู่กับ Balanced accuracy
Accuracy อย่างเดียวจะสูงเกินจริงเสมอ เพราะโซนส่วนใหญ่ไม่มีปัญหา โมเดลที่ตอบว่า "ไม่มีสิว" ทุกโซนก็ได้ accuracy สูงแล้ว
ส่วน threshold ปรับบน valid แล้วใช้ค่าเดิมกับ test จึงไม่ได้ปรับให้เข้ากับ test set

### ถ้า Macro-F1 ยังไม่ถึง 80%
ลองทีละข้อ แล้วเทียบกันด้วย `report_test.md`
1. ใช้โมเดลใหญ่ขึ้นและภาพละเอียดขึ้น: `--arch efficientnet_b2 --img 288 --batch 32`
2. ดูในตาราง per-class ว่าคลาสไหนต่ำ ปกติจะเป็น redness และ eyebag ซึ่งมีข้อมูลน้อยที่สุด
   ทางแก้ที่ได้ผลที่สุดคือเพิ่มภาพหรือ label ของคลาสนั้น การปรับพารามิเตอร์ช่วยได้น้อยกว่า
3. ถ้าต้องการสอนโมเดลว่าผิวใสเป็นอย่างไร และแน่ใจว่าภาพที่ไม่มี label เป็นผิวใสจริง ให้สร้าง dataset ใหม่ด้วย `--trust-empty-images`
4. ตรวจ label เพิ่มด้วย `review_tool` (หัวข้อ 3.5) โดยเฉพาะภาพ train ที่มีรอยแดง/ถุงใต้ตา วิธีนี้ช่วยได้มากที่สุด

## 3.5 ตรวจ/แก้ label ด้วย review_tool

ปัญหาหลักของ dataset ไม่ใช่ label ผิด (polygon เดิมค่อนข้างแม่น) แต่คือ **label ไม่ครบ** แต่ละแหล่งภาพ label ไว้แค่บางคลาส
เครื่องมือนี้ให้คนดูใบหน้าที่แบ่งโซนแล้ว และยืนยันคำตอบครบทั้ง 6 ปัญหา × ทุกโซน ใช้เวลาประมาณ 10–15 วินาทีต่อภาพ
ภาพที่บันทึกแล้วจะมี label ครบ ไม่เหลือค่า "ไม่ทราบ"

```bat
review_labels.bat
```

หน้าเว็บจะเปิดขึ้นที่ `http://127.0.0.1:8765` เปิดได้จากเครื่องนี้เท่านั้น
ผลการตรวจบันทึกลง `zone_reviews.jsonl` ทุกครั้งที่กดบันทึก จะปิดกลางทางแล้วกลับมาทำต่อเมื่อไรก็ได้

- **ลำดับภาพ:** test → valid → train (ใน train จะขึ้นภาพที่มีรอยแดง/ถุงใต้ตาและภาพที่มีช่อง "?" เยอะก่อน)
- **สีในตาราง:** ม่วงเข้ม = มี (จาก label เดิมหรือคุณติ๊ก) · ส้ม "AI" = โมเดลเสนอว่ามี · กรอบประ "?" = ยังไม่มีใครตอบ · "–" = ปัญหานี้ไม่เกิดในโซนนี้
- **คีย์ลัด:** `↑↓` เลือกโซน · `1`–`6` ติ๊ก · `Enter` บันทึกและไปภาพถัดไป · `→` ข้าม · `X` ภาพใช้ไม่ได้ · `B` แสดงกรอบ label เดิม
- **ช่องที่ไม่ติ๊กจะบันทึกว่า "ไม่มี"** ภาพที่ไม่ต้องแก้อะไรก็ให้กด Enter เพื่อยืนยันว่าตรวจแล้ว

### ขั้นตอนที่แนะนำ
1. **รอบ 1 — ตรวจ test (และ valid ถ้ามีเวลา) โดยไม่มี AI ช่วย:** รัน `review_labels.bat` เฉยๆ
   test set มีใบหน้าประมาณ 600–800 ภาพ ควรตรวจให้ครบ หรืออย่างน้อย 400 ภาพ (ประมาณ 1.5–2 ชั่วโมง)
2. **เทรนรอบแรก:** รัน `run_zone_training.bat` ซึ่งจะเจอ `zone_reviews.jsonl` แล้วใช้
   `--reviews zone_reviews.jsonl --eval-reviewed-only` ให้เอง ตัวเลขใน `report_test.md` จะวัดเฉพาะภาพที่คนตรวจแล้ว
3. **รอบ 2 — ตรวจ train โดยมี AI ช่วย:** `review_labels.bat --model runs_zone\<รัน>\best.pt`
   โมเดลจะติ๊กเสนอเฉพาะช่องที่มั่นใจ ≥ 60% ให้แก้เฉพาะที่ผิด เน้นภาพที่มีรอยแดง/ถุงใต้ตา
4. **เทรนใหม่** แล้วเทียบ `report_test.md` กับรอบก่อน ทำรอบ 2–4 ซ้ำจนได้ตามเป้า

**ทำไม test ไม่มี AI ช่วย:** คนมักกดยืนยันตามช่องที่ถูกติ๊กไว้แล้ว ถ้า test label เอียงเข้าหาคำตอบของโมเดล
คะแนน test จะสูงเกินจริง เครื่องมือจึงไม่แสดงคำแนะนำ AI ใน test (เปิดได้ด้วย `--ai-on-test` แต่ไม่แนะนำ)
ในบท methodology เขียนได้ว่า "label ของชุดทดสอบตรวจสอบโดยผู้วิจัยโดยไม่มีคำแนะนำจากโมเดล"

**ทำไมไม่ใช้ YOLO เดิมเติม label ที่ขาดอัตโนมัติ:** ทดลองแล้ว โมเดล `skin_analysis_farmasi.pt` ทำนายแต่ละคลาสเฉพาะในภาพจากแหล่งที่เคย label คลาสนั้น
เช่น ในภาพชุด oily-skin ที่ทดลองไม่ทำนายสิวเลยสักจุด เพราะตอนเทรนมันเรียนรู้จาก label ที่ขาดชุดเดียวกันนี้ การให้โมเดลนี้เติม label จึงแทบไม่ได้ข้อมูลใหม่

## 3.6 ตรวจ test สองคนแยกกัน + วัด Cohen's kappa

ใช้เมื่ออยากยืนยันว่า label ของ test เชื่อถือได้ (กรรมการมักถามว่า "ใครเป็นคนตัดสินว่ามีสิว")
ผู้ตรวจสองคนตรวจภาพชุดเดียวกัน **โดยไม่ดูคำตอบของอีกคน** แล้วเทียบกัน

1. สร้าง zone dataset เฉพาะ test: `build_zone_dataset.py ... --splits test --out zone_dataset_test`
2. ผู้ตรวจ A (คุณ): `review_labels.bat` → บันทึกลง `zone_reviews.jsonl`
   ผู้ตรวจ B: บันทึกลง `zone_reviews_claude.jsonl` (หรือไฟล์ของผู้ตรวจคนที่สอง) **อย่าเปิดดูไฟล์นี้ก่อนตรวจเสร็จ**
3. เทียบผล: `compare_reviews.bat` → `review_compare\agreement.md` (ตรงกันกี่ %, kappa ต่อปัญหา) และ `disagreements.csv`
4. ตัดสินช่องที่ไม่ตรงกัน: `compare_reviews.bat adjudicate` หน้าเว็บจะขึ้นเฉพาะภาพที่ตอบต่างกัน
   ช่องที่ทั้งคู่ตอบตรงกันถูกเติมไว้แล้ว ช่องที่มีขอบประสีแดงคือช่องที่ต้องตัดสิน (มุมซ้ายล่างบอกว่า A และ B ตอบอะไร) → บันทึกลง `zone_reviews_adjudicated.jsonl`
5. รวมเป็น label สุดท้าย: `compare_reviews.bat final` → `review_compare\zone_reviews_final.jsonl`
6. เทรน/วัดผลด้วย `--reviews review_compare\zone_reviews_final.jsonl --eval-reviewed-only`

**อ่านค่า kappa:** > 0.8 ตรงกันเกือบสมบูรณ์ · 0.6–0.8 มาก · 0.4–0.6 ปานกลาง · < 0.4 ต่ำ (Landis & Koch, 1977)
ปัญหาไหน kappa ต่ำ แปลว่าแม้แต่คนสองคนก็ยังเห็นไม่ตรงกัน ไม่ควรคาดหวังให้โมเดลได้ F1 สูงกว่าระดับนี้มาก
ในเล่มเขียนได้ว่า "ชุดทดสอบตรวจโดยผู้ตรวจ 2 คนอย่างเป็นอิสระ ได้ Cohen's kappa = … และตัดสินกรณีที่ไม่ตรงกันโดยผู้วิจัย"

หมายเหตุ: หน้าตรวจของผู้ตรวจ A จะติ๊กช่องตาม polygon เดิมไว้ให้ก่อน ส่วนผู้ตรวจ B (Claude) ตรวจจากภาพอย่างเดียวโดยไม่เห็น label เดิม
ถ้าต้องการให้เงื่อนไขเท่ากันทุกประการ ให้ผู้ตรวจ A ตัดสินจากภาพจริง ไม่ใช่กดยืนยันตามช่องที่ติ๊กไว้
